# Third-party notices

`dist/avif_enc.js` and `dist/avif_enc.wasm` are the single-thread AVIF encoder from
[jSquash](https://github.com/jamsinclair/jSquash) `@jsquash/avif` 2.1.1, Apache License 2.0.
jSquash's codec and wrapper code derive from
[Squoosh](https://github.com/GoogleChromeLabs/squoosh) (Apache License 2.0). The
WebAssembly module statically contains:

- [libavif](https://github.com/AOMediaCodec/libavif) 1.0.1 (BSD 2-Clause). Its `src/obu.c`
  is by the VideoLAN and dav1d authors, also BSD 2-Clause.
- [libaom](https://aomedia.googlesource.com/aom/) 3.7.0 (BSD 2-Clause, with the Alliance for
  Open Media Patent License 1.0). Its encoder compiles in two third-party sources
  (`av1/av1.cmake`, `AOM_AV1_ENCODER_SOURCES`):
  - `third_party/fastfeat` (BSD 3-Clause, Copyright (c) 2006, 2008 Edward Rosten), the corner
    detector behind libaom's global-motion search.
  - `third_party/vector` (MIT, Copyright (c) 2016 Peter Goldsborough). It is compiled in; whether
    any of it survives linking could not be confirmed in the stripped wasm.
- libsharpyuv, from [libwebp](https://chromium.googlesource.com/webm/libwebp/) at commit
  `e2c85878f6a33f29948b43d3492d9cdaf801aa54` (BSD 3-Clause, with Google's WebM additional IP
  rights grant).
- [Emscripten](https://emscripten.org/) (MIT and University of Illinois/NCSA Open Source
  License, dual-licensed): `avif_enc.js` is Emscripten-generated glue, and the module carries
  Emscripten's runtime and embind.
- The runtime libraries the Emscripten toolchain links into every module: LLVM libc++ and
  libc++abi (Apache License 2.0 with LLVM Exceptions, text at
  [llvm-project](https://github.com/llvm/llvm-project); the LLVM Exceptions let it be
  redistributed in object form without the Apache notice conditions, so it is not reproduced)
  and musl libc (MIT).

The versions are from jSquash's codec build files and the "AOMedia Project AV1 Encoder v3.7.0"
string inside the wasm. The licence texts for jSquash, libavif, libaom (with fastfeat and
vector), libsharpyuv, Emscripten and musl are reproduced below, because the Alliance for Open
Media Patent License, the BSD, MIT and Apache licences ask for them to travel with binaries.

The Ultra HDR and ISO 21496-1 byte layouts follow Google's
[libultrahdr](https://github.com/google/libultrahdr) (Apache License 2.0) and the Android
Ultra HDR Image Format v1.1 specification. They were read for the format; no code is copied.
